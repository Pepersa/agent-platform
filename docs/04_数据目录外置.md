# 04 · 数据目录外置（`AGENT_DATA_DIR`）

> 目标：**把平台运行期产生的全部数据文件整体挪到任意盘符**，
> 只需要改一个环境变量 `AGENT_DATA_DIR`；
> **不设该变量时行为与改造前逐字节一致**（向后兼容）。

---

## 1. 为什么要做这件事

平台运行期会持续产生落盘数据：

| 文件 | 用途 | 体积量级 |
|---|---|---|
| `sessions.db` | 会话与消息（SQLite + WAL） | 数 MB，且持续增长 |
| `kb/chunks.db` | 知识库 chunk + 向量索引（SQLite） | 数 MB |
| `kb/chunk_manifest.json` | chunk 清单（评测集 gold 校对用） | 数百 KB |
| `audit/audit.db` | 审计日志（SQLite + WAL） | 数 MB |
| `workspace.db` | 工作区撤销栈（SQLite） | 数百 KB |
| `models.json` | 自定义模型注册表（原子写） | 几 KB |
| `custom_tools.json` | 自定义工具定义（原子写） | 几 KB |
| `*.log` | 运行日志（llama / api / eval） | 数 MB |
| `shots/` `obs_shots/` `ui_ws_shots/` `eval_reports/` | 截图与评测产物 | 数十 MB |

这些文件原本**硬编码**在 `<repo>/data/` 下。带来的问题：

1. **换盘必须搬整个项目目录**（代码 + 权重 + 数据混在一起）；
2. 项目目录可能落在**只读盘 / 网络盘 / 版本控制目录**里；
3. 大文件污染代码仓库（`.gitignore` 之外还要额外维护）；
4. 「代码」与「数据」生命周期不同 —— 代码要版本化，数据要备份/归档。

> **不在本任务范围**：C 盘上的 conda/miniconda Python 环境与 pip 缓存
> （那才是真正吃空间的大头）。本方案只管**项目自己的数据目录**。

---

## 2. 核心机制

### 2.1 唯一的环境变量

```bash
# Windows cmd
setx AGENT_DATA_DIR "D:\agent-data"

# PowerShell（当前会话生效）
$env:AGENT_DATA_DIR = "D:\agent-data"

# Linux / macOS
export AGENT_DATA_DIR=/mnt/d/agent-data
```

指向**任意盘符**都可以（`D:\`、`E:\`、`\\NAS\share\agent-data`）。
目录**不存在时会自动创建**（连同各子目录）。

### 2.2 优先级

```
显式参数（函数入参） > 环境变量 AGENT_DATA_DIR > 项目默认 <repo>/data
```

第三档就是**向后兼容的锚点**：不设环境变量时，所有路径与改造前完全一致。

### 2.3 统一解析入口

所有数据路径都收敛到 `agent_platform/core/paths.py`：

```python
from agent_platform.core import paths

paths.data_dir()              # -> <数据根目录>
paths.data_path("sessions.db")  # -> <数据根目录>/sessions.db
paths.data_path("kb", "chunks.db")  # -> <数据根目录>/kb/chunks.db
paths.kb_dir()                # -> <数据根目录>/kb
paths.audit_dir()             # -> <数据根目录>/audit
paths.ensure_data_dirs()      # 确保根目录 + 各子目录存在（幂等）
paths.data_dir_info()         # 诊断信息（/health 用）
```

### 2.4 受影响的数据文件

| 路径 | 归属模块 |
|---|---|
| `sessions.db` | `core/session_store.py` |
| `models.json` | `core/model_registry.py` |
| `custom_tools.json` | `core/custom_tools.py` |
| `workspace.db` | `core/workspace.py`（撤销栈） |
| `audit/audit.db`、`audit/audit.jsonl` | `core/audit.py` |
| `kb/chunks.db`、`kb/chunk_manifest.json`、`kb/uploads/` | `knowledge/store.py`、`knowledge/admin.py` |
| `docs/`、`reports/`、`outbox/notify.jsonl` | `knowledge/tools_ext.py` |
| `eval_reports/` | `eval/runner.py` |
| `api_out.log`、`api_err.log` | `scripts/restart_api.py` |

**验证生效**：`GET /health` 会返回 `data_dir` 字段：

```json
"data_dir": {
  "dir": "D:\\agent-data",
  "exists": true,
  "external": true,
  "source": "env"
}
```

`external: false` 表示还在项目目录内（未外置）。

## 3. 迁移步骤

### 3.1 先看要搬什么（dry-run，不动任何文件）

```bash
python scripts/migrate_data_dir.py --to D:\agent-data --dry-run
```

输出示例：

```
======================================================================
数据目录迁移计划
======================================================================
  来源 : E:\PYPROJECT\agent\data
  目标 : D:\agent-data
  文件 : 176 个
  体积 : 21.8 MB
  排除 : scripts/（保留在原处）
----------------------------------------------------------------------
    sessions.db                                  4.4 MB
    audit/audit.db                               4.4 MB
    audit/audit.db-wal                           3.9 MB
    kb/chunks.db                                 2.9 MB
    models.json                                    636 B
    ...
======================================================================
[dry-run] 未做任何改动。去掉 --dry-run 即可执行实际迁移。
```

### 3.2 停掉 API（重要）

数据库文件被进程占用时迁移会**拒绝执行**（Windows 上独占锁）：

```bash
python scripts/restart_api.py --port 8010   # 先停掉旧的
```

或者直接结束占用 8010 端口的进程。

### 3.3 执行迁移

```bash
python scripts/migrate_data_dir.py --to D:\agent-data
```

行为说明：

- **逐个文件**移动，**不覆盖**目标目录里的同名文件 —— 有冲突时**中止**并列出冲突清单
  （加 `--force` 可强制覆盖）；
- 迁移前检查 `.db` / `.db-wal` / `.db-shm` 是否被占用，占用则拒绝迁移；
- `data/scripts/` **默认不移动**（见 §4.2）；
- 迁移后在**新目录**写 `data_dir.json`（记录迁移来源、时间、文件数、体积）；
- 在**原目录**留 `MIGRATED_TO.txt`（人看的说明，含恢复方法）。

可选参数：

| 参数 | 作用 |
|---|---|
| `--dry-run` | 只打印清单，不动文件 |
| `--copy-only` | 只复制不删除源文件 |
| `--include-scripts` | 连同 `data/scripts/` 一起迁移 |
| `--force` | 目标目录同名文件强制覆盖 |
| `--from` | 指定源目录（默认 `<repo>/data`） |

### 3.4 设置环境变量并重启

```bash
# Windows cmd（永久）
setx AGENT_DATA_DIR "D:\agent-data"

# 或者只在启动脚本里临时指定
python scripts/restart_api.py --port 8010 --data-dir "D:\agent-data"
```

`restart_api.py` 启动日志会打印最终生效的数据目录：

```
[env] 数据目录 = D:\agent-data  (来源: --data-dir)
```

### 3.5 确认

```bash
curl http://127.0.0.1:8010/health
```

看 `data_dir.external == true`、`data_dir.dir == "D:\\agent-data"` 即可。

### 3.6 回滚

1. 把 `AGENT_DATA_DIR` 指回 `<repo>/data`（或删除该变量）；
2. 原目录里的 `MIGRATED_TO.txt` 说明文件可以删掉。

> ⚠️ 迁移是**移动**（默认），源文件已不在原目录。
> 若想保留双份，迁移时加 `--copy-only`。

## 4. 两个需要留意的细节

### 4.1 `data/scripts/` 默认保留在原处

`data/scripts/demo_custom_tool.py` 这类文件是**用户自定义工具脚本**，
在 `custom_tools.json` 里以**仓库根相对路径**被引用：

```json
{
  "name": "vf_script_demo",
  "kind": "script",
  "config": { "script_path": "data/scripts/demo_custom_tool.py",
              "function_name": "echo_tool" }
}
```

`core/custom_tools.py` 的 `resolve_script_path()` 解析顺序：

1. 绝对路径 → 直接用；
2. **仓库根**相对路径（`data/scripts/demo_tool.py`）→ 以仓库根为基准；
3. **数据目录**相对路径（`scripts/demo_tool.py`）→ 以数据目录为基准。

所以**即使数据目录整体挪走**，这些脚本仍然能找到（前提是 `data/scripts/`
留在仓库里 —— 这正是迁移脚本默认排除它的原因）。

若确实想把它一起挪走：用 `--include-scripts`，并把配置里的路径改成
`scripts/demo_tool.py`（数据目录相对路径）。

### 4.2 工作区文件不受影响

`workspace.py` 的**撤销栈**（`workspace.db`）跟随数据目录，
但**工作区里的代码文件**仍在工作区根目录（默认 `<repo>`），
由 `WORKSPACE_ROOT` 环境变量控制 —— 这跟数据目录是两件事。

## 5. 向后兼容保证

| 场景 | 结果 |
|---|---|
| 不设 `AGENT_DATA_DIR` | 所有路径与改造前**完全一致**（`<repo>/data/...`） |
| 已有 `data/models.json` 自定义模型条目 | **不会丢**（默认路径未变） |
| 已有 `data/sessions.db` 历史会话 | **不会丢**（默认路径未变） |
| 已有 `data/kb/chunks.db` 索引 | **不会丢**（默认路径未变） |
| `custom_tools.json` 里 `data/scripts/...` 引用 | **不会断**（仓库根 fallback） |
| 回归测试（56+ 项） | 全部通过 |

> ⚠️ **已知抖动**：`verify_web_ui.py` 的 HITL 段（第 4 节）依赖
> **LLM 主动发起工具调用** —— gpt-oss 偶尔只口头说「需要确认」而不真正调用，
> 此时会失败 6 项。脚本自带 8 次重试，但极端情况下仍会抖。
> 这是**改造前就存在**的行为，与数据目录无关。

> ⚠️ **环境约束**：`verify_kb_rebuild_persistence.py` 会跑 4 遍全量
> BGE-M3 向量化。本机 GPU 显存已被 llama-server 占用到
> 15669/16303 MiB 时，`build_index.py --rebuild` 子进程会**卡在加载
> bge-m3 权重**上（CPU 占用为 0，表现为「无响应」而非报错）。
> 这是**显存不足**导致，与数据目录改造无关。
> 单独验证重建路径可用 `--embed-backend hash`（秒级完成）。

实现上的三个约束：

1. **纯 Python 标准库**，不新增任何第三方依赖；
2. 路径解析**无副作用** —— `data_dir()` 只解析不建目录，
   建目录由 `ensure_data_dirs()` 显式负责；
3. 所有默认值都用 `None` 哨兵 + **运行时**解析，
   避免「模块导入时就把环境变量读死」的问题。
